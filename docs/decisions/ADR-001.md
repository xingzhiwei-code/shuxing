# ADR-001：多端策略——v0 纯 Web，M3 引入 Tauri

> 状态：已采纳（2026-10-06 用户拍板）| 相关：roadmap §4、PRD v0 §F8

## 背景

数形目标为 Web + 桌面端多端（用户明确要求用 Tauri）。
需要决定：v0 是否直接上 Tauri，还是分期。

## 决策

- **v0 只做纯 Web**（HTML / CSS / TypeScript + Vite），验证"拖参数看图像"模式的速度优先。
- **M3（开源发布 v0.1）时同步引入 Tauri**，出桌面离线版（Windows / macOS），覆盖教室无网场景。
- **移动端暂不启动**（PWA / Tauri mobile 后议）；但 v0 保持响应式，手机浏览器可用。

## 理由

1. **验证速度**：v0 的核心风险是模式验证（学生/家长看得懂吗），不是多端；Tauri 构建（多平台打包、CI）会拖慢 v0。
2. **零成本推迟**：前端写成纯 Web 应用（无 Node 运行时依赖），Tauri 壳随时可套，`tauri dev` 即可进入开发模式；推迟没有架构代价。
3. **离线是真实场景**：教室、山区经常没网，桌面离线包有明确价值，值得在 M3 做，而不是砍掉。
4. **移动端形态差异大**：手机交互（手势、竖屏信息架构）与桌面差异大，单独立项，不在 v0 发散。

## 后果

- 前端代码**禁止**引入 Node 运行时依赖；所有能力必须能在纯浏览器环境运行。
- 全站颜色走 CSS 变量（Dark Mode 预留，见宪法附录标准 9）。
- M3 需补：Tauri 配置、应用图标、多平台构建 CI、离线资源打包清单。
- 如未来要做移动端，需另立 ADR（PWA vs Tauri mobile 选型）。

## 备选（已否决）

- v0 直接 Tauri 起手：否决，拖慢验证，且 v0 并无离线强需求。
- Electron：否决，包体积大，与"轻量工具"定位不符；Tauri 的 Rust 后端 + 小体积更合适。
