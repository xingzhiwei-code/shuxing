## 1. 背景与目标

**背景**：中文交互式数学可视化工具，灵感来自抖音"粒子先生"的交互式物理仿真
（电阻工坊："拖电阻看电流"）与 3Blue1Brown 的系列化数学可视化。
中文区没有原生头部的数学可视化工具，这是空位。

**v0 目标**：
1. 验证"拖参数看图像"这一 killer 交互模式（学生/家长愿意用、看得懂）
2. 上线 S1a 函数系列全部 3 个知识点：一次函数、二次函数、反比例函数
3. 开源发布 v0.1（GitHub 公开仓库 + README + 演示 GIF + MIT）

**非目标**（明确不做，见 roadmap 红线）：
- S1b（几何）/ S1c（代数）/ S1d（统计概率）及后续系列
- Tauri 桌面包（M3 才出，v0 只做纯 Web，但架构预留）
- 导出 GIF/视频（v3）、移动端 App、用户系统/登录、后端服务
- 算法可视化、AI 可视化、英语可视化

## 3. 功能需求

### F1 · 一次函数可视化 `y = kx + b`
- 坐标系：网格 + x/y 轴，固定视图（v0 不做缩放平移）
- 滑杆：k ∈ [-3, 3] step 0.05；b ∈ [-5, 5] step 0.1；iOS 风格滑杆（见原型）
- 实时渲染：拖动时图像实时跟随，目标 60fps（宪法标准 2）
- 标注：
  - k > 0 上升 / k < 0 下降 / k = 0 水平直线（文字标注实时切换）
  - b：与 y 轴交点 (0, b) 高亮打点
- 边界诚实：k = 0 时明确标注"此时为水平直线 y = b"
- 三段式内容（F4 范式）：
  - 概念引入（一句话）："一次函数的图像是直线，k 管倾斜方向和程度，b 管上下平移。"
  - 交互探索（引导任务 2 个）："把 k 拖到 2，再拖到 -2，观察直线怎么转" / "固定 k = 1，拖 b，看直线上下走"
  - 例题验证（1 道）："已知一次函数 y = 2x - 1，当 x = 3 时 y = ?"（答案可展开：5）

### F2 · 二次函数可视化 `y = ax² + bx + c`
- 滑杆：a ∈ [-3, 3] step 0.1；b ∈ [-6, 6] step 0.2；c ∈ [-6, 6] step 0.5
- 标注：
  - 顶点 `(-b/2a, (4ac-b²)/4a)` 打点 + 坐标文字
  - 对称轴 `x = -b/2a` 虚线
  - 与 y 轴交点 (0, c)；与 x 轴交点（按判别式 Δ = b²-4ac：Δ>0 两个交点 / =0 一个 / <0 无，打点并文字说明）
  - a > 0 开口向上 / a < 0 开口向下；|a| 越大开口越窄（文字提示）
- **边界诚实（宪法第 3 条）**：a = 0 时**不得**画抛物线——明确提示"a = 0 时退化为一次函数 y = bx + c"，图像切换为直线渲染。这是 P0 级正确性要求。
- 三段式内容：
  - 概念引入："二次函数图像是抛物线，a 管开口方向和宽窄，顶点是最值点。"
  - 交互探索："拖 a 从 1 到 -1，看抛物线怎么翻过去" / "调 b、c，观察顶点轨迹"
  - 例题验证："抛物线 y = x² - 4x + 3 的顶点坐标是？"（答案：(2, -1)）

### F3 · 反比例函数可视化 `y = k/x`
- 滑杆：k ∈ [-6, 6] step 0.5，k ≠ 0（滑杆跳过 0，或 k=0 时提示无意义——**不得**画出图像）
- 标注：
  - k > 0 分布在一、三象限 / k < 0 分布在二、四象限（文字实时切换）
  - 渐近线：x = 0 与 y = 0 虚线，标注"x ≠ 0"
  - **k 的几何意义**：在曲线上任取一点（可拖动），向坐标轴作垂线形成矩形，实时标注矩形面积 = |k|（这是本知识点的 killer 演示）
- 三段式内容：
  - 概念引入："反比例函数图像是双曲线，k 决定分支位置，|k| 决定矩形面积。"
  - 交互探索："拖 k 从 2 到 -2，看分支怎么跳象限" / "拖动曲线上的点，看矩形面积变不变"
  - 例题验证："若点 (2, 3) 在反比例函数图像上，k = ?"（答案：6）

### F4 · 三段式内容范式（页面结构）
每个知识点页固定三段（见 roadmap §5）：
1. **概念引入**：≤ 100 字一句话 + 核心公式，公式用专用排版
2. **交互探索**：可视化主区（Canvas）+ 2–3 个引导任务（"试试把 k 拖到 x"）
3. **例题验证**：1 道中考风格典型题，答案默认折叠可展开
- 全部文案须过 L2（yiyi 教研审核）；PRD 中的示例文案为初稿，实施时以审核版为准

### F5 · iOS 交互标准落地
- 以 `prototype/ios-style-reference.html` 为**唯一实现参考**：直接复制其 CSS 变量、
  动效曲线（`cubic-bezier(.32,.72,.35,1)`）、滑杆/按钮/卡片组件代码，保持全站一致
- v0 必须项：跟手 60fps（标准 2）、spring 动效（标准 1）、按压缩放 0.97（标准 4）、
  配色 ≤ 3 种（标准 6）、统一圆角（标准 7）、排版（标准 8，数字 tabular-nums）、
  Dark Mode 架构预留（标准 9：全站 CSS 变量，不写死颜色）
- v0 可暂缓：Dark Mode 完整实现（v1）、sheet 下滑关闭（v0 无 sheet 场景）、
  prefers-reduced-transparency 降级（有则加分，无不扣分）

### F6 · 极简导航
- v0 只有 3 个知识点：首页三卡片（一次函数 / 二次函数 / 反比例函数），iOS 分组列表风格
- 不做章节树（v1 roadmap 已规划）

### F7 · 性能与兼容
- Canvas 渲染，devicePixelRatio 适配，网格密度低端机自动降级
- 目标：主流手机/桌面浏览器 60fps；低端机 ≥ 30fps 可接受
- 兼容：Chrome / Safari / Edge 最新两个大版本；移动端 Safari 重点验证触摸拖拽

### F8 · 工程约束
- 纯 Web（HTML / CSS / TypeScript）+ Vite 构建；不引入重型图表库（手写 Canvas，保证 60fps 与包体积）
- 前端无 Node 运行时依赖，为 Tauri 预留（ADR-001）：`tauri dev` 可直接套壳，v0 不出包
- 开源 MIT；README 含愿景、一句话介绍、演示 GIF、本地运行方式

## 6. 附：给编码 agent 的教研备注（L2 前置意见）

1. 二次函数 a 的滑杆**必须**允许经过 0，0 是最好的教学点（"退化"概念），不要为了省事把 0 抠掉。
2. 反比例函数 k 的几何意义矩形，默认取第一象限分支上一点，拖动点时矩形实时跟随。
3. 例题选中考真题风格，不要自编偏题；答案解析一句话讲清思路。
4. 所有"文字实时切换"（如 k>0 上升）必须和图像状态严格一致，不一致就是 P0 bug。
